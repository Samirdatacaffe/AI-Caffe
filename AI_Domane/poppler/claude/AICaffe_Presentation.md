## SLIDE 1 — What is AICaffe?

AICaffe is an **AI-powered chat platform** that brings together multiple AI models and industry-specific intelligence into one place.

Instead of switching between ChatGPT, Claude, and other tools — your users get **one unified interface** that understands their industry.

```
                    ┌─────────────────────────────┐
                    │          AICaffe             │
                    │                             │
                    │   "Ask anything about your  │
                    │    industry — we route it    │
                    │    to the right AI model     │
                    │    with the right context."  │
                    │                             │
                    └─────────────────────────────┘
```

**In simple terms:** Think of AICaffe as a smart receptionist that knows which expert to send your question to — whether it's about ESG compliance, election data, workforce analytics, insurance, or general data analysis.

## SLIDE 4 — How It Works (User Journey)

### Step-by-Step Flow

```
  ┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐
  │         │     │         │     │         │     │         │     │         │
  │ VISIT   │────>│ SIGN UP │────>│ CHOOSE  │────>│ CREATE  │────>│  CHAT   │
  │ LANDING │     │ / LOGIN │     │ DOMAINS │     │ PROJECT │     │ WITH AI │
  │ PAGE    │     │         │     │ (up to 3)│    │         │     │         │
  │         │     │         │     │         │     │         │     │         │
  └─────────┘     └─────────┘     └─────────┘     └─────────┘     └─────────┘
```

### Detailed Walkthrough

**Step 1 — Landing Page**
> User discovers AICaffe through the marketing website. They see features, available AI models, and pricing plans (Individual / Team).

**Step 2 — Sign Up or Login**
> Three ways to get started:
> - Enter email and verify with a 6-digit OTP code
> - Register with email and password
> - One-click Google sign-in

**Step 3 — Choose Your Domains**
> User picks up to 3 areas of interest: ESG, Election, Workforce, DataCaffe, or Insurance. The platform personalizes their experience based on this.

**Step 4 — Create a Project**
> User creates a named project (e.g., "Q4 ESG Audit") with custom colors and icons to organize their work.

**Step 5 — Start Chatting**
> User selects an AI model, picks a solution domain, types (or speaks) their question, attaches documents if needed, and gets a real-time streaming response.

## SLIDE 6 — AI Models & Domain Routing

### Available AI Models

| Model | Best For |
|---|---|
| **Kimi-k2.5** | General-purpose queries (default) |
| **Qwen3 Coder** | Code generation and technical tasks |
| **GPT (OpenAI)** | Creative writing, reasoning |
| **Claude Sonnet 4.6** | Analysis, long documents, safety |
| **Mistral Large 3** | Multilingual and European data |

### Domain-Specific Solutions

| Solution | What It Does |
|---|---|
| **Brew Generic** | General AI assistant — works for any topic |
| **ESG** | Understands ESG frameworks, regulations, and compliance — powered by RAG with ESG knowledge base |
| **Election** | Election data analysis, trend forecasting, demographic insights |
| **DataCaffe** | Data processing, analytics, and visualization assistance |

### How Routing Works

```
  User asks: "What are the latest SEBI ESG disclosure requirements?"

       ↓ User selected "ESG" solution domain

  ┌──────────────────────┐
  │  LangGraph Service   │ ← Checks ESG knowledge base (RAG)
  │  (Python Backend)    │ ← Adds domain-specific context
  │                      │ ← Routes to best model
  └──────────┬───────────┘
             ↓
  ┌──────────────────────┐
  │  AI Model responds   │ ← With ESG-specific knowledge
  │  with streaming      │ ← Token by token in real-time
  └──────────────────────┘
```

> **Key Insight:** The user doesn't need to know which model to pick. They just select their domain, and the system handles the rest.

## SLIDE 7 — File Upload & Document Analysis

### Supported File Types

```
  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐
  │ PDF  │  │ DOCX │  │ CSV  │  │ JSON │  │ IMG  │  │ TXT  │
  └──────┘  └──────┘  └──────┘  └──────┘  └──────┘  └──────┘
                     Max 10 MB per file
```

### How It Works

```
  1. User uploads a document (e.g., "Annual_ESG_Report.pdf")
             ↓
  2. System parses and extracts text content
             ↓
  3. Text is injected into the AI prompt as context
             ↓
  4. AI reads the document and answers questions about it

  Example:
  User: "Summarize the key risks from the attached report"
  AI:   [Reads the uploaded PDF and provides a structured summary]
```

> **Why this matters:** Users can have the AI analyze their own private documents — reports, spreadsheets, legal files — without manually copying content.

## SLIDE 8 — Security & Authentication

### Three Ways to Sign In

```
  ┌─────────────────┐   ┌─────────────────┐   ┌─────────────────┐
  │                 │   │                 │   │                 │
  │  Email + OTP    │   │  Email +        │   │  Google         │
  │  Verification   │   │  Password       │   │  One-Click      │
  │                 │   │                 │   │                 │
  │  6-digit code   │   │  Encrypted      │   │  OAuth 2.0      │
  │  via email      │   │  with bcrypt    │   │  auto-signup    │
  │  5 min expiry   │   │                 │   │                 │
  └─────────────────┘   └─────────────────┘   └─────────────────┘
```

### Security Measures

| Layer | Protection |
|---|---|
| **Passwords** | Hashed with bcrypt (industry standard, irreversible) |
| **Tokens** | JWT with 15-minute access + 10-day refresh tokens |
| **Cookies** | HTTP-only (cannot be stolen by JavaScript attacks) |
| **Rate Limiting** | Max 10 login attempts per minute per IP |
| **OTP Protection** | Max 4 attempts per code, auto-expires in 5 minutes |
| **Session Tracking** | Every login records device, browser, IP, and location |
| **Multi-Device Control** | Users can see all active sessions and revoke any one |
| **Password Reset** | OTP-verified, invalidates all old sessions on reset |

> **For the client:** This is enterprise-grade security. Every login is tracked, every token expires, every password is encrypted. Users have full control over their sessions.

## SLIDE 10 — Data Model (What We Store)

### Simple View

```
  USER
   │
   ├── has many SESSIONS (login records with device/IP/location)
   │
   ├── has one WORK PROFILE (selected domains: ESG, Election, etc.)
   │
   ├── has many PROJECTS
   │       │
   │       └── each project has many CONVERSATIONS
   │
   └── has many STANDALONE CONVERSATIONS (no project)
           │
           └── each conversation has many MESSAGES
                   │
                   └── each message can have ATTACHMENTS (files)
```

### What Each Stores

| Entity | Key Data |
|---|---|
| **User** | Email, name, encrypted password, avatar, verification status |
| **Session** | Device type, browser, IP address, location, last active time |
| **Project** | Name, description, color, icon, archive status |
| **Conversation** | Title, linked project (optional), timestamps |
| **Message** | Role (user/AI), text content, timestamp |
| **Attachment** | File name, type, size, storage path |
| **Work Profile** | Selected industry domain, custom input |
